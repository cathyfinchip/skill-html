ACT I · Orientation

More than a prompt: a complete adaptation workflow

novel-outline accepts a source novel and target parameters, then manages plot cuts, character merges, beat placement, episode design, and production-asset calculations. You approve the direction before the full outline is written.

OUTPUT 01

Adaptation decisions

Core premise, keep/cut/merge decisions, risks, and verbatim evidence traceable to the novel.

OUTPUT 02

Characters and beats

Character tiers and arcs, plus major/minor beats placed across the episode run.

OUTPUT 03

Episode outlines

Every episode contains a synopsis, opening hook, and closing suspense beat in narrative prose.

OUTPUT 04

Production assets

Automatically calculated characters, locations, props, reuse plans, episode appearances, and generation risks.

It does not simply finish an outline. It turns novel adaptation into a standardized process that can be approved, quality-checked, and carried forward into production.

Long novels: use chunk to split the manuscript by chapter, normally 15 chapters per volume. If headings cannot be detected, it falls back to size-based splitting. The tool supports up to 60 volumes and reports truncated explicitly rather than silently dropping the ending.

Every major adaptation decision can be traced back to the novel

Important retained elements include verbatim evidence in keep[].evidence. This reduces invented details, relationship errors, and adaptation decisions based only on memory.

ACT III · Dramaturgy Review

Step two: approve the skeleton before full drafting

The most valuable checkpoint happens before complete episode writing. First review three decisions: which plotlines were cut, which characters were merged, and where the major turning points land.

Send the adaptation brief to your agent

Provide the novel, episode count, duration, genre, adaptation mode, and non-negotiable story elements.

Use the novel-outline skill to adapt the complete public-domain English text of Jane Austen’s Pride and Prejudice into a 10-episode vertical short drama, with each episode approximately 2 minutes long. Keep the Elizabeth–Darcy relationship, the first-proposal rejection, Lydia and Wickham’s scandal, and Darcy’s transformation. First generate and validate the quick outline skeleton. Wait for my approval before writing complete episode synopses.

The skill reads the text and builds a skeleton

The first draft contains adaptation, characters, scenes, and beats. The episodes array remains empty.

Run beat-stage validation

node scripts/novel-outline.mjs validate outline.json --stage beats

This catches pacing gaps and major-turn timing before the expensive episode-writing stage.

Approve the direction

Review cuts, merges, and turning points. Reply Approved only when the skeleton reflects the intended adaptation.

Draft all episodes and validate the full outline

Episode writing is batched in groups of no more than ten, merged into the JSON, and validated until every gate passes.

CHECKPOINT · USER APPROVAL REQUIRED

Why the workflow pauses here

A wrong skeleton costs one planning pass. Discovering the same structural error after dozens of episodes have been written can invalidate the entire outline.

ACT V · Structured Production Data

Why the outline is represented as code

The creator does not need to become a programmer. Structure simply turns creative decisions into data that can be counted, checked, traced, and handed to the next production stage.

Stable identifiers

Characters, scenes, and props use consistent IDs across every episode.

Breakage detection

When an upstream item changes, validation locates every outdated or missing reference.

Automatic asset math

Appearance counts, episode usage, location reuse, and asset workload are calculated from the structure.

Downstream continuity

The same outline.json can feed character, art, and screenplay workflows.

ACT VI · Terminal Lab

Terminal commands: chunk, validate, diagnose, render

The agent reads and adapts the novel. The deterministic tool operates on the source text and completed outline.json.

Split a long manuscript

node scripts/novel-outline.mjs chunk book.txt /tmp/wk

Validate an outline

node scripts/novel-outline.mjs validate outline.json # Optional stages: --stage skeleton | beats | full

Run only the fourteen quality gates

node scripts/novel-outline.mjs checkup outline.json

Render reports and calculate assets

node scripts/novel-outline.mjs render outline.json --html > outline-report.html node scripts/novel-outline.mjs render outline.json --html --lang en > outline-report.html node scripts/novel-outline.mjs assets outline.json

Run deterministic self-tests

node scripts/selftest.mjs
Checkup mode: you do not need to regenerate an existing outline. The quality panel acts as a diagnostic report. Failed gates do not prevent rendering because surfacing the problems is the purpose of the mode.

Appendix · Troubleshooting

Common error: MODULE_NOT_FOUND

The problem is usually the working directory

scripts/novel-outline.mjs is a relative path. If the command is run from the home directory, Node looks for the script in the wrong location.

Two reliable fixes

# Option 1: enter the skill directory first cd /path/to/novel-outline node scripts/novel-outline.mjs checkup /absolute/path/to/outline.json # Option 2: use the absolute script path node /absolute/path/to/novel-outline/scripts/novel-outline.mjs checkup /absolute/path/to/outline.json
